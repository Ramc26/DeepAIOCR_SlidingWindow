Never Lose Document Continuity Across Page Boundaries.

Isolated per-page LLM calls misclassify continuation pages (like invoice line items on Page 5 missing the header from Page 4). Our engine classifies every page using a stateful 3-page sliding window [Page N−1 + Label, Page N, Page N+1].

Deliverable 1 & 2 • Architecture

Built for Fault-Tolerant Sequential State

Designed in classifier.py and design.md to handle multi-page boundaries, transient API failures, and strict allow-list validation without halting batch jobs.

1. State Carry-Forward

Page N receives the validated classification of Page N−1 alongside its extracted text, resolving multi-page invoices and contracts that lack repeated headers.

2. Boundary Guards

Page 1 has no previous neighbor (previous_page: null) and the final page has no next neighbor (next_page: null). Payloads truncate cleanly at MAX_PAGE_CHARS=12000.

3. UNKNOWN Fault Isolation

If Page 45 fails after MAX_RETRIES=2, it emits label: null, status: "failed". Page 46 still receives Page 45's text, but predicted_label: "UNKNOWN"—never poisoning downstream context with Other.

4. Allow-List Validation

Malformed JSON, wrong schema shapes, or hallucinated labels outside {Invoice, Purchase Order, Contract, Appendix, Other} automatically trigger backoff retries.

prompt.md — System Prompt & Contract
Strict Allow-List
# System Prompt Constraints

You are a document page classifier. Classify ONLY target_page into exactly one allowed label:
"Invoice" | "Purchase Order" | "Contract" | "Appendix" | "Other"

1. Use previous_page (text + predicted_label) and next_page (text) solely as supporting evidence for multi-page continuations.
2. Never classify neighbor pages.
3. If predicted_label == "UNKNOWN", rely on the raw text of previous_page.
4. Respond strictly with valid JSON:

"response_schema": {
  "label": "Invoice | Purchase Order | Contract | Appendix | Other"
}
